# 自定义置入滤镜流程

把第三方 `.cube` 滤镜转成 DxO ONE 机内 CC 表，并替换到存储卡上的某个档位。
本目录是这条流程的**发布版工具**：转换内核经独立测试验证，文档写明每一步
能保证什么、不能保证什么。

## 目录内容

| 文件 | 说明 |
|---|---|
| `cube2dxo.py` | 转换内核（与 `工具/cube2dxo.py` 逐字节一致，改动须双向同步） |
| `test_cube2dxo.py` | 独立测试：轴序、输入域、量化误差、坏输入（8 项） |
| `转换滤镜.command` | macOS 双击壳：拖 `.cube` 上去即可转换 |
| `README.md` | 本文档 |

## 验证状态

**已验证**（`python3 test_cube2dxo.py`，共 10 项）：

- 恒等复合 100% 还原原厂表（16,384 字节 LUT 区逐字节一致，需原厂参照表环境）；
- **直通模式**：恒等 LUT 逐字节还原参照自身；红蓝交换 LUT 的纯红/纯蓝/绿
  节点映射逐一核对（发行版环境可跑）；
- RGB 轴序、`DOMAIN_MIN/MAX`、`LUT_3D_INPUT_RANGE` 解析正确；
- 10 bit 量化误差有界（≤ 约 0.125 / 255，需原厂参照表环境）；
- 输出不在插值前裁剪，坏输入（坏头 / NaN / 越界）会报错而不是静默出错表。

> 依赖原厂参照表的测试在参照表缺失时才跳过；本仓库已自带
> `stock/Imx183_Cc_Still1.bin`，正常应 **10/10 全过**。

**未验证**（工具自己也会在运行时打印警示）：

- 相机 CC 表的输出编码是否等于源 LUT 要求的输入编码——**没有仪器校准**，
  文件能写进去、格式能解回来，不等于色彩链路物理正确；
- `neutral` 是主动抵消灰轴影调的风格选项，**不是** Log / 色域转换；
- **直通模式的产物未实机验证**（含尾部曲线填 0 的假设）。

## 第一步：转换

```bash
# 复合模式（默认，与仓库成品十档相同配方——参照表已随仓库提供）
python3 cube2dxo.py 你的滤镜.cube --tone neutral

# 复合模式（默认，与仓库成品十档相同配方——参照表已随仓库提供）
python3 cube2dxo.py 你的滤镜.cube --tone neutral

# 直通模式（可选：纯滤镜直出，无原厂基础影调，观感与成品十档不同）
python3 cube2dxo.py 你的滤镜.cube --tone pass --direct
```

| 参数 | 说明 |
|---|---|
| `--direct` | **直通模式**（可选）：输出 = 纯滤镜直出，不读参照表 |
| `--tone` | `pass` 原样直出 / `neutral` 中灰归一（默认）/ `blend` 混合 |
| `--strength` | `blend` 时 neutral 权重 0..1（默认 0.65） |
| `--bw` | 去色后套 LUT（黑白） |
| `--name` / `--outdir` | 输出文件名 / 目录（默认 `<仓库根>/成品/lut/`） |

输出 `<名字>.bin` 是 **17,536 B 整表**；`_s0..s4.bin` 是写卡用的 5 槽载荷
（五槽地址各不相同，槽 0 单槽载荷仅供实验，完整切换用五槽）。
直通产物文件名自动带 `_direct` 后缀，与复合产物区分。

### 原厂参照表（已随仓库提供）

复合模式需要一个 17,536 B 的**原厂参照表** `Imx183_Cc_Still1.bin`（从 DxO
原厂固件 ROMFS 提取的相机色彩表）。它随仓库放在 `stock/` 下——这是 DxO 的
版权内容，经发布者决定随包分发，仅供个人转换研究使用；**权利人可随时要求
移除**（见 [THIRD_PARTY.md](../THIRD_PARTY.md)）。

转换器按 `本目录/stock/ → 仓库根/固件镜像/…` 顺序自动查找，两种安装方式
（下载 ZIP / git clone）都开箱即用，无需任何额外步骤。

`--direct` 直通模式仍然可用：跳过参照表，效果是"纯滤镜直出"，少了原厂
基础影调那一层，与仓库成品十档的观感**会不同**；尾部 1024 B 曲线填 0，
原厂表上实测尾部改动无效果，但直通产物本身未实机验证。

> `DOMAIN_MIN/MAX` 的重映射作用在输入端——这是确定行为；若你的源 LUT 依赖
> DOMAIN 改输出范围，转换结果会不符合预期，先改源或用 `pass`。

## 第二步：置入存储卡（替换档位）

**当前菜单是"登记制"**：`ph_menu.bin` 里编译期登记了 10 个档位
（`DXO_FILTERS/lut_*.bin`，每个 87,720 B = 5 槽 × 17,536 B + 头），
菜单**不会自动扫描**新文件。

所以自定义滤镜的置入方式是**替换某个现有档位的内容**：

1. 把转换输出的 5 个槽载荷按地址拼成 87,720 B 五槽包
   （或直接用整表 ×5 + 20 B 头自行打包）；
2. 覆盖卡上 `DXO_FILTERS/lut_<档>.bin`——**文件名必须不变**，
   菜单名也不变（例如替换 `lut_gold.bin` 后菜单仍显示 `G200`）；
3. 逐文件回读 SHA-256 比对；
4. 正常弹出卷，装回相机开机。

**红线**：绝不碰 `DCIM/`、`touch_prefs.bin`、`dxot/`；不用通配符批量覆盖；
一次只动一个明确列出的文件。

**要新增档位**（而不是替换）需要重建 `ph_menu.bin` 登记新文件名——那是
构建流程，不是置入流程，本目录不覆盖。

## 交给 AI 客户端（提示词）

````text
你是我的文件操作助手。请把我指定的一个 .cube 滤镜转换后置入 DxO ONE 相机
存储卡，替换一个现有档位。严格按步骤执行，不要跳步。

【前置检查】
1. 确认 Python3 与 numpy 可用；进入仓库的 自定义置入滤镜流程/ 目录。
2. 运行 python3 test_cube2dxo.py，10 项应全部通过（本仓库自带 stock/ 参照表），
   有任何 FAIL 或 skipped 就停下问我。
3. 确认 SD 卡已挂载（macOS /Volumes/，Windows 盘符），卡根有 DXO_FILTERS/ 与 DCIM/；
   没有 DCIM/ 说明选错卷，立即停。

【转换】
4. 问我用哪种模式（默认复合）：不加参数 = 复合模式（与仓库成品十档同配方，
   生成 <名字>_neutral.bin）；加 --direct = 直通模式（纯滤镜直出，观感不同，
   文件名带 _direct 后缀）。然后运行
   python3 cube2dxo.py "<我的.cube路径>" [--tone neutral | --tone pass --direct]
   记下输出的 <名字>_<后缀>_s0..s4.bin 五个槽载荷
   （每个 = 8 字节头 {u32 地址, u32 长度} + 17,536 B 表）。

【打包】
5. 按槽地址从小到大拼接成 87,720 B 五槽包：20 B 文件头（5×{地址,长度}）+ 5×17,536 B 表体；
   长度不是 87,720 B 就停下问我，不要自己"修"。

【置入】
6. 问我要替换哪个档位（lut_orig / lut_vel / lut_gold / lut_port / lut_hp5 /
   lut_posi / lut_hibw / lut_fuyu / lut_kyus / lut_sato 之一），文件名不变。
7. 备份卡上原文件到卡外目录（存在才备份），再覆盖 DXO_FILTERS/<档位>.bin。

【安全红线】
- 绝不动 DCIM/、touch_prefs.bin、dxot/、autoexec.ash、ph_menu.bin、ph_probe.ash。
- 只操作明确列出的路径，不用通配符、不 rm。

【验收】
8. 逐文件回读卡上内容算 SHA-256，与打包结果比对一致；
9. 执行 sync，正常弹出卷。汇报：测试结果、替换的档位、备份位置、校验结果、是否成功弹出。
````

## 已知边界（重申）

- CC 表输入线性 / 输出 sRGB 的匹配**未做仪器校准**，不宣称与原机或胶片实物一致；
- 本流程只置换**内容**，不改变菜单结构；菜单名与档位的对应关系以
  主 README 的十档表为准；
- 转换内核与本目录文档改动前，先跑 `test_cube2dxo.py`。
