# 自定义置入滤镜流程

把第三方 `.cube` 滤镜转成 DxO ONE 机内 CC 表，并替换到存储卡上的某个档位。
本目录是这条流程的**发布版工具**：转换内核经独立测试验证，文档写明每一步
能保证什么、不能保证什么。

## 目录内容

| 文件 | 说明 |
|---|---|
| `cube2dxo.py` | 转换内核（与 `工具/cube2dxo.py` 逐字节一致，改动须双向同步） |
| `重登记指纹.py` | 换完档位内容后，同步更新 `ph_menu.bin` 的指纹登记（见"指纹锁"章节）；只重登记，不增删档位 |
| `管理滤镜.py` | 增 / 删 / 改清单的模板补丁构建器：重建 `ph_menu.bin` 让菜单同步扩张/收缩（见"增删档位"章节） |
| `test_cube2dxo.py` | 转换内核独立测试：轴序、输入域、量化误差、坏输入（10 项） |
| `test_重登记指纹.py` | 重登记工具独立测试：两代布局 no-op 回归、篡改恢复、坏输入（16 项） |
| `test_管理滤镜.py` | 管理滤镜独立测试：ARM 编码、no-op 回归、增删分发、CLI 与安全闸（42 项，纯标准库） |
| `verify_unicorn_管理滤镜.py` | 可选离线门：vendored unicorn 真执行菜单分发，逐 idx 捕获名字（依赖实验层 deps） |
| `转换滤镜.command` | macOS 双击壳：拖 `.cube` 上去即可转换 |
| `README.md` | 本文档 |

## 验证状态

**已验证**（`python3 test_cube2dxo.py`，共 10 项）：

- 恒等复合 100% 还原原厂表（16,384 字节 LUT 区逐字节一致，需原厂参照表环境）；
- **直通模式**：恒等 LUT 逐字节还原参照自身；红蓝交换 LUT 的纯红/纯蓝/绿
  节点映射逐一核对（发行版环境可跑）；
- RGB 轴序、`DOMAIN_MIN/MAX`、`LUT_3D_INPUT_RANGE` 解析正确；
- 10 bit 量化误差有界（≤ 约 0.125 / 255，需原厂参照表环境）；
- 输出不在插值前裁剪，坏输入（坏头 / NaN / 越界）会报错而不是静默出错表。

> 依赖原厂参照表的测试在参照表缺失时才跳过；本仓库已自带
> `stock/Imx183_Cc_Still1.bin`，正常应 **10/10 全过**。
>
> 重登记工具另有一套独立测试（`python3 test_重登记指纹.py`，16 项）：
> 对 Build 69（10 档）与 Build 71（11 档）两种布局做 no-op 回归
> （工具输出必须与输入逐字节一致）、篡改指纹后恢复、缺包/坏包/拒绝原地覆盖。
> 其中用到 Build 71 现场的 2 项在该实验目录缺失时自动跳过。

> 增删工具 `管理滤镜.py` 另有独立测试（`python3 test_管理滤镜.py`，42 项，纯标准库）：
> ARM 编码器、Build 69/71 的 menu 与 ph_menu no-op 逐字节回归、规范布局与增删的
> 静态分发校验、包指纹提取、CLI 增删/容量/安全闸。另有一道**可选**离线门
> `verify_unicorn_管理滤镜.py`（vendored unicorn 真执行菜单分发，逐 idx 捕获名字，
> 覆盖 n=10/11/12 与增删场景）。
>
> **以上均为离线验证**（静态解码 + 仿真执行 + 逐字节回归）。增删后的菜单
> **尚未实机验收**——实机切换/显示须由你亲自上机确认，工具与文档不替您下"通过"结论。

**未验证**（工具自己也会在运行时打印警示）：

- 相机 CC 表的输出编码是否等于源 LUT 要求的输入编码——**没有仪器校准**，
  文件能写进去、格式能解回来，不等于色彩链路物理正确；
- `neutral` 是主动抵消灰轴影调的风格选项，**不是** Log / 色域转换；
- **直通模式的产物未实机验证**（含尾部曲线填 0 的假设）。

## 第一步：转换

```bash
# 复合模式，与仓库成品十档相同配方（pass = 源影调原样保留，参照表已随仓库提供）
python3 cube2dxo.py 你的滤镜.cube --tone pass

# 风格选项：中灰归一（源 LUT 自带整体染色时用来抵消灰轴，观感与成品十档不同）
python3 cube2dxo.py 你的滤镜.cube --tone neutral

# 直通模式（可选：纯滤镜直出，无原厂基础影调，观感与成品十档不同）
python3 cube2dxo.py 你的滤镜.cube --tone pass --direct
```

| 参数 | 说明 |
|---|---|
| `--direct` | **直通模式**（可选）：输出 = 纯滤镜直出，不读参照表 |
| `--tone` | `pass` 源影调原样保留（**成品十档即此配方**）/ `neutral` 中灰归一（工具默认）/ `blend` 混合 |
| `--strength` | `blend` 时 neutral 权重 0..1（默认 0.65） |
| `--bw` | 去色后套 LUT（黑白） |
| `--name` / `--outdir` | 输出文件名 / 目录（默认 `<仓库根>/成品/lut/`） |

输出 `<名字>.bin` 是 **17,536 B 整表**；`_s0..s4.bin` 是写卡用的 5 槽载荷
（五槽地址各不相同，槽 0 单槽载荷仅供实验，完整切换用五槽）。
直通产物文件名自动带 `_direct` 后缀，与复合产物区分。

### 原厂参照表（已随仓库提供）

复合模式需要一个 17,536 B 的**原厂参照表** `Imx183_Cc_Still1.bin`（从 DxO
原厂固件 ROMFS 提取的相机色彩表）。它随仓库放在 `stock/` 下——这是 DxO 的
版权内容，经发布者决定随包分发，仅供个人转换研究使用；**权利人可随时要求
移除**（见 [THIRD_PARTY.md](../THIRD_PARTY.md)）。

转换器按 `本目录/stock/ → 仓库根/固件镜像/…` 顺序自动查找，两种安装方式
（下载 ZIP / git clone）都开箱即用，无需任何额外步骤。

`--direct` 直通模式仍然可用：跳过参照表，效果是"纯滤镜直出"，少了原厂
基础影调那一层，与仓库成品十档的观感**会不同**；尾部 1024 B 曲线填 0，
原厂表上实测尾部改动无效果，但直通产物本身未实机验证。

> `DOMAIN_MIN/MAX` 的重映射作用在输入端——这是确定行为；若你的源 LUT 依赖
> DOMAIN 改输出范围，转换结果会不符合预期，先改源或用 `pass`。

### ⚠️ 指纹锁：换内容必须同步更新 `ph_menu.bin` 登记

`ph_menu.bin` 的切换核心带**内容指纹校验**：每次切换档位时，取装载后的
槽 2 / 槽 5 表体 `0x1000` 偏移处各 4 字节，与构建时登记的指纹比对，
**不符就拒绝切换**（界面停在原档位，像是"滑不动"）。

这意味着：**只替换 `lut_*.bin` 内容、不动 `ph_menu.bin`，被替换的档位
将无法切换**——这是设计行为（防篡改），不是文件坏了。症状与恢复：

- 症状：能进滤镜菜单，但滑到被替换的档位时滤镜不切换，其余档位正常；
- 恢复：把替换前的原文件拷回 `DXO_FILTERS/` 即可（所以置入前必须备份）；
- 正确姿势：换内容后用 **`重登记指纹.py`** 同步更新登记，一步到位：

```bash
# 不动输入文件，输出 <ph_menu>.reg.bin；每次替换内容后都要重跑一遍
python3 重登记指纹.py ph_menu.bin DXO_FILTERS -o ph_menu.new.bin
```

  工具按卡上/仓库的 `ph_menu.bin` 逐档列出指纹变化（Build 69 的 10 档与
  Build 71 的 11 档及更高档数通用），把输出文件替换卡根的 `ph_menu.bin`
  （先备份原件）即可。**`ph_menu.bin` 只能用本工具生成，不要手改**。

## 第二步：置入存储卡（替换档位）

**当前菜单是"登记制"**：`ph_menu.bin` 里编译期登记了 10 个档位
（`DXO_FILTERS/lut_*.bin`，每个 87,720 B = 5 槽 × 17,536 B + 头），
菜单**不会自动扫描**新文件。

所以自定义滤镜的置入方式是**替换某个现有档位的内容**：

1. 把转换输出的 5 个槽载荷按地址从小到大**首尾相接**，拼成 87,720 B 五槽包
   （布局 = 5 段交错的「8 B 头{地址,长度} + 17,536 B 表体」，**不是** 20 B
   集中头；直接把 `_s0.._s4.bin` 依次拼接即可）；
2. 覆盖卡上 `DXO_FILTERS/lut_<档>.bin`——**文件名必须不变**，
   菜单名也不变（例如替换 `lut_gold.bin` 后菜单仍显示 `G200`）；
3. 跑 `python3 重登记指纹.py ph_menu.bin DXO_FILTERS -o ph_menu.new.bin`
   重登记指纹，备份卡上 `ph_menu.bin` 后用输出文件替换（逐字节回读校验）；
4. 逐文件回读 SHA-256 比对；
5. 正常弹出卷，装回相机开机。

> 第 3 步与第 2 步是**一套**：只做 2 不做 3，被替换的档位会因指纹不符
> 拒绝切换；只做 3 不做 2，登记与实际内容不符，同样拒切。

**红线**：绝不碰 `DCIM/`、`touch_prefs.bin`、`dxot/`；不用通配符批量覆盖；
一次只动一个明确列出的文件。

**新增 / 删除档位**：`重登记指纹.py` 只做"换内容后重登记"，**不增删档位**
（档位数不变；缺包时它会直接报错拒绝生成）。要增删档位、让菜单同步扩张/收缩，
用 **`管理滤镜.py`**（见下节"增删档位"）——它在已验证菜单模板上重建分发链、
循环上限与指纹区，**离线已验证、实机验收待您亲自做**。只想临时不用某个档位，
留着不切即可，不必删。

## 增删档位（管理滤镜.py）

`重登记指纹.py` 只能在**档位数不变**的前提下换内容；要**新增 / 删除**档位、
让菜单同步扩张或收缩，用 `管理滤镜.py`。它是**模板补丁构建器**：以发布层
`patch/ph_menu.bin`（Build 69）为模板，只重写随清单变化的 `menu.text` 分发链/
名字串、`core.text` 立即数、`STR` 路径与指纹区，**其余固件补丁段逐字节保留**。
不需要您侧装 Xcode/clang，`ph_menu.bin` 仍由工具生成（不手改二进制）。

```bash
# 列出模板登记清单（idx / 名字 / 卡路径 / 指纹 / 预装档）
python3 管理滤镜.py list ../patch/ph_menu.bin

# 新增一档（菜单同步扩张）：名字限字模字符集 ≤6 字符，包是 87,720 B 五槽包
python3 管理滤镜.py add ../patch/ph_menu.bin --name SATOBI --pkg DXO_FILTERS/lut_sato.bin -o ph_menu.new.bin

# 删除一或多档（菜单同步收缩、重新索引）：按 idx 或名字，可重复
python3 管理滤镜.py delete ../patch/ph_menu.bin --idx 9 --idx 5 -o ph_menu.new.bin
python3 管理滤镜.py delete ../patch/ph_menu.bin --name R-HIBW --name KYUSHU -o ph_menu.new.bin

# 按 JSON 清单全量重建（{filters:[{name,pkg}], preload?}）
python3 管理滤镜.py rebuild ../patch/ph_menu.bin --manifest manifest.json --pkg-dir DXO_FILTERS -o ph_menu.new.bin

# 无参数 = 逐字节回归自检
python3 管理滤镜.py
```

**输入约束**（工具会校验并拒绝非法输入）：

- 名字 ≤6 字符，且只用字模字符集 `-025ABEFGHIKLNOPRSTUVWY`（缺 C D J M Q X Z
  与数字 1 3 4 6 7 8 9）；名字须唯一；
- 卡路径以 `c:\DXO_FILTERS\` 开头、<32 B；新包须是 87,720 B 五槽包，槽地址合规；
- 各档 slot1 指纹须互不相同（否则无法区分滤镜）；档位数 1..12（STR 区上限）；
- 删除至少保留 1 档；`--preload` 指定开机预装档（缺省沿用模板，越界取 0）。

**安全闸**（与全流程红线一致）：

- **离线工具，绝不写相机卡**：只读模板、在工作目录生成输出文件；拒绝原地覆盖
  输入，拒绝写入 `/Volumes/`（可移动卷）。把输出拷进卡是**另行授权**的手动步骤；
- 删除只移除菜单**登记**：卡上对应 `lut_*.bin` 变成未引用文件（留着无害，是否
  手动清理由您决定），工具不碰卡上任何文件；
- 增删后的 `ph_menu.bin` 与其余档位包文件**必须同套使用**，不要只换一半。

**LOG 信标**：`ph_menu.bin` 的 `LOG_HDR` 带 4 字节构建信标（69=`D5GP`、
71=`F5GP`），实机验收时用来确认运行的是哪套。默认**沿用模板信标**；加
`--custom-magic` 写入自定义信标 `C5GP`(0x50473543)，便于在日志里把自定义构建
与原厂 69 区分（也可 `--magic 0x........` 显式指定）。是否改用自定义信标由您
在验收时决定。

**验证状态**：离线已验证——`test_管理滤镜.py`（42 项）+ 可选 unicorn 真执行门
（逐 idx 分发可达、名字正确，覆盖 n=10/11/12 与增删）。**实机切换/显示尚未
验收**，须由您亲自上机确认；未实机确认前不写成"已通过"。

## 交给 AI 客户端（提示词）

````text
你是我的文件操作助手。请把我指定的一个 .cube 滤镜转换后置入 DxO ONE 相机
存储卡，替换一个现有档位。严格按步骤执行，不要跳步。

【前置检查】
1. 确认 Python3 与 numpy 可用；进入仓库的 自定义置入滤镜流程/ 目录。
2. 运行 python3 test_cube2dxo.py，10 项应全部通过（本仓库自带 stock/ 参照表），
   有任何 FAIL 或 skipped 就停下问我。
3. 确认 SD 卡已挂载（macOS /Volumes/，Windows 盘符），卡根有 DXO_FILTERS/ 与 DCIM/；
   没有 DCIM/ 说明选错卷，立即停。

【转换】
4. 问我用哪种模式（默认复合成品配方）：--tone pass = 复合模式（与仓库成品十档
   同配方，生成 <名字>.bin）；--tone neutral = 中灰归一（CLI 不加参数的默认，
   观感与成品十档不同，生成 <名字>_neutral.bin）；--tone pass --direct = 直通
   模式（纯滤镜直出，观感不同且未实机验证，文件名带 _direct 后缀）。然后运行
   python3 cube2dxo.py "<我的.cube路径>" --tone pass
   （按我的选择改用 --tone neutral 或 --tone pass --direct）
   记下输出的 <名字>[_后缀]_s0..s4.bin 五个槽载荷
   （每个 = 8 字节头 {u32 地址, u32 长度} + 17,536 B 表）。

【打包】
5. 把 5 个槽载荷按地址从小到大首尾相接成 87,720 B 五槽包：每槽 = 8 B 头
   {地址,长度} + 17,536 B 表体，5 段交错排列（不是 20 B 集中头 + 5 表体）；
   长度不是 87,720 B 就停下问我，不要自己"修"。

【置入】
6. 问我要替换哪个档位（卡上 DXO_FILTERS/ 里的 lut_*.bin 之一），文件名不变。
7. 备份卡上原 lut_<档位>.bin 与 ph_menu.bin 到卡外目录（存在才备份），
   再覆盖 DXO_FILTERS/<档位>.bin。
8. 运行 python3 重登记指纹.py ph_menu.bin DXO_FILTERS -o ph_menu.new.bin，
   向我展示它列出的指纹变化表，确认无误后用 ph_menu.new.bin 替换卡根的
   ph_menu.bin（原文件已备份）。

【安全红线】
- 绝不动 DCIM/、touch_prefs.bin、dxot/、autoexec.ash、ph_probe.ash。
- 只操作明确列出的路径，不用通配符、不 rm。

【指纹锁警告——必读】
- ph_menu.bin 对每个档位登记了内容指纹；替换 lut_*.bin 后必须用
  重登记指纹.py 同步更新登记，两步缺一不可，否则该档位拒绝切换。
- ph_menu.bin 只能用重登记指纹.py 生成的新文件替换；不要手改二进制、
  不要跳过第 8 步、不要只换 lut 文件或只换 ph_menu。

【验收】
9. 逐文件回读卡上内容算 SHA-256（含新 ph_menu.bin），与本地结果比对一致；
10. 执行 sync，正常弹出卷。汇报：测试结果、替换的档位、指纹变化、备份位置、校验结果、是否成功弹出。
````

### 增删档位提示词（管理滤镜.py）

